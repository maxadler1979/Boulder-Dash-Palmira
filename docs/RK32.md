# Порт на стандартный Радио-86РК, 32 КБ

Не «ужать Пальмиру», а собрать ту же игру под классику:
ОЗУ `0000–7FFF`, штатный знакогенератор **2×2**, без PIT, без RAM-шрифта.

Пальмиру не ломаем. Это второй таргет.

## Что выкидываем

| В мусор | Зачем было | Что вместо |
|---------|------------|------------|
| `title.c` целиком: PALMIRA-стена, Claude, буквы BOULDER DASH, мелодия, PIT-SFX | заставки и звук | старт сразу в пещеру; выбор пещеры — строка ASCII |
| `zg8x12[768]`, `set_pseudograph()`, `copy_zg()`, `clear_chargen_ram()`, RU10/TM9 | свой знакогенератор 2×3 | штатные коды 2×2 мозаики + ASCII ROM |
| `bitmap[0xCCC+…]`, `put_bitmap` | мёртвый буфер ~3.4 КБ | удалить |
| Спрайты цифр/алфавита в `title.c` (`d0_dig`, `l_a`…`l_z`, `Digits[]`) | HUD и меню картинкой | `put_char` / `put_text` |
| Двухканальный PIT, джинглы, `sid2pit` | тон | `EI`/`DI` цоки |
| Бонусные пещеры Q–T (`CaveBonusQZx`…`TZx`, 97+124+96+124 = 441 байт + параметры) | C64 bonus | 16 пещер A–P, после P снова A |

Демо с титульника уезжает вместе с `show_title()`. `DemoMoveData[64]` в логике можно оставить на потом или тоже снять.

## Что оставляем как есть

- Физика C64: `game_logic.c`, `work_cave[880]`, 16 пещер A–P
- Окно **12×10** (в таблице адресов сейчас 11 строк × 12, поле с ряда 3)
- Тайл **6×4 знакоместа**, 24 байта на кадр — тот же блитер `show_window` / шаг 73
- Idle/ходьба Rockford, алмазы, критеры, амёба — те же таблицы кадров, **картинку перерисовать под 2×2**

Внутри знакоместа было 2×3 (6 пикселей, коды `00–3F`). Станет 2×2 (4 пикселя, коды `00–0F`). Коробка на экране та же (6×4 знака), детализация клетки грубее. Массивы 24 байта остаются, меняется смысл байта.

## Кадр и карта памяти

Окно **11×8**, тайл 6×4. ВГ75 считает **38** строк кадра (`VG75_TIMING_ROWS` — тайминг/vsync).  
В ОЗУ **36×78** байт; последний байт `F3` (EOS). Хвост кадра ВГ75 заполняет без ПДП — частота не прыгает.  
(Упаковка пустых строк одним `F1`/EOR давала сдвиг картинки — не используем.)

```
0000 – ~6ABF   код + BSS
6AC0           таблица смещений + стек вниз (REGISTER_SP=27328)
6B08 – 75FF    видеобуфер VIDEO_LEN=2808
7600 – 76CF    ячейки монитора РК — НЕ ТРОГАТЬ
```

**Жёсткий верхний предел записи: `0x75FF`.** Код до `0x6AC0`.  
Не ставить число строк ВГ75 = размеру ОЗУ.

Defines: `SCREEN=0x6B08`, `SM_Y_ADDR=0x6AC0` (`RK86/main.h`).

Классика 25×64 даже не рассматриваем — тогда либо резать окно, либо отказаться от «той же картинки».

## HUD и меню — ASCII

Одна текстовая строка сверху (знакоместа 0–1, 78 колонок), штатный шрифт:

```
A  150  D 12/12  L 3  001250
```

Пещера, секунды, алмазы, жизни, счёт — обычные символы монитора, не `put_sprite`.  
«Титульник»: `BOULDER DASH` + `CAVE A` + `SPACE=START` тремя `put_text`. Без стены, без лого.

Коды букв — как в мониторе РК (верхний регистр / КОИ-7). Никакой латиницы из `l_a[]`.

## Спрайты 6×4 на 2×2

`show_window` / `sw_blit` / `screen_adresses`: окно **11×8** (`WIN_W`/`WIN_H`), `lab_x = 6` (центр), `lab_y += 4`, шаг строки cave `+29`.
`shadow[88]`. Раньше задумывали 12×10 — в 38 строках ВГ75 по Y влезает только 8 тайлов.

Пустой тайл = код пустоты ROM, не «все нули знакогенератора».

## Звук: EI / DI цоки

Питча нет, только щелчки. На классике INT почти не используется (vsync и так поллится с `C001`), поэтому:

```
; один цок
EI
DI
```

События — пачки разной длины, не частоты:

| событие        | пачка      |
|----------------|------------|
| шаг / копание  | 1 цок      |
| топанье idle   | 2          |
| валун          | 3–4        |
| алмаз          | 6–8        |
| взрыв          | 12–16      |

Звать из тех же `sound_event` / `sound_tap`, внутри — цикл EI/DI. Не из горячего скана 800 клеток: как сейчас, с события. В `tick_wait` можно доливать пачку, если событие ещё «звучит» счётчиком.

Громкость и тембр зависят от машины (динамик на INT/магнитофоне). На эмуляторе может быть тихо — это норма.

## Итог по ощущению

Играется тот же Болдер: 16 основных пещер A–P, та же физика, окно 11×8. Выглядит беднее внутри клетки (4 точки вместо 6). Есть меню, 1-канальная мелодия, демо. Нет бонусных Q–T. Верхний предел записи — **`0x75FF`**; код не должен подползти к `0x6AC0`.
